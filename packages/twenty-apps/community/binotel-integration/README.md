# Binotel Integration (Twenty App)

Интеграция с украинской облачной телефонией **Binotel** — принимает webhook-события о звонках, сохраняет их в отдельном объекте `Звонок` и автоматически привязывает каждый завершенный звонок к записи в объекте **Заявки** по совпадению номера телефона.

## Возможности

- Отдельный объект **Звонок Binotel** (`binotelCall`) с историей всех звонков
- Webhook-эндпоинт `POST /binotel/webhook` с опциональной проверкой секрета
- Upsert по `generalCallID`: один и тот же звонок не создается дважды при нескольких событиях
- Автолинковка к **Заявкам**: при завершении звонка ищется Заявка, у которой в **любом** PHONES-поле номер совпадает с номером внешнего абонента (primary phone)
- Все поля с русскими лейблами
- Секретный API-ключ Binotel хранится как `serverVariable` (шифруется)

## Настройка

### 1. Переменные приложения

После установки приложения заполни в настройках workspace → Applications → Binotel:

| Переменная                | Описание                                                         | Обязательна |
| ------------------------- | ---------------------------------------------------------------- | ----------- |
| `BINOTEL_API_KEY`         | API key из личного кабинета Binotel (company key)                | да          |
| `BINOTEL_API_SECRET`      | API secret                                                       | да          |
| `BINOTEL_WEBHOOK_SECRET`  | Опциональный секрет для проверки входящих webhook-запросов       | нет         |

### 2. Webhook URL

После установки приложения Twenty генерирует публичный URL вида:

```
https://<your-twenty-host>/apps/<app-id>/binotel/webhook
```

Скопируй его и укажи в личном кабинете Binotel в разделе **Интеграции → Webhooks** для следующих событий:

- `call_started` (необязательно — создаст запись со статусом «В процессе»)
- `call_completed` (обязательно — именно тут проставляется статус, длительность, запись и происходит автолинковка к Заявкам)

Если задал `BINOTEL_WEBHOOK_SECRET` — добавь его в Binotel как query-параметр `?secret=...` или как HTTP-хедер `X-Binotel-Secret: <secret>`. Запросы без валидного секрета будут отвергаться с кодом ошибки.

### 3. Автолинковка к Заявкам (очень важно)

В первой версии приложения связь с «Заявками» хранится в TEXT-поле `zayavkaId` объекта **Звонок**. Это сделано потому, что universal-identifier кастомного объекта «Заявки» существует только в твоём workspace и не может быть захардкожен в пакете.

Чтобы в интерфейсе получить **кликабельную связь** «Звонок ↔ Заявка», выполни один раз следующее:

1. Открой **Настройки → Data model → Заявки**
2. Добавь новое поле:
   - Тип: **Relation**
   - Relation type: **One to many**
   - Related object: **Звонок** (из приложения Binotel)
   - Label: `Звонки`
   - Name: `binotelCalls`
3. На противоположной стороне (объект **Звонок**) Twenty автоматически создаст обратное поле. Зайди в его настройки и убедись, что:
   - Label: `Заявка`
   - Name: `zayavka`
   - Join column name: `zayavkaId`  ← **это ключевая деталь**

После этого webhook-handler, записывая `zayavkaId`, будет автоматически создавать полноценную relation-связь, и в UI у каждой Заявки появится таб со списком звонков, а у каждого Звонка — переход на связанную Заявку.

Если UI Twenty не позволяет указать конкретный `joinColumnName`, просто оставьте поле `zayavkaId` как есть — оно будет хранить UUID Заявки в виде текста, и ссылку можно будет сделать вручную или через формулу.

### 4. Как работает матчинг

При событии `call_completed` (или любом другом «завершенном» событии):

1. Из payload берется номер внешнего абонента:
   - для входящих — `callerID`
   - для исходящих — `calleeID`
2. Номер нормализуется: удаляются все не-цифры, 0-префикс заменяется на украинский код `380`, сохраняется вариант с `+`, а также «хвост» из 9 цифр как fallback.
3. Через Metadata API запрашивается список **всех активных PHONES-полей** объекта **Заявки** (`nameSingular: zayavka`).
4. Строится GraphQL-фильтр вида «любое из этих полей содержит любой из вариантов номера» и запрашивается первая подходящая Заявка.
5. Её `id` записывается в поле `zayavkaId` звонка.

Если Заявка не найдена — звонок сохраняется без привязки, это нормально.

> **Внимание:** сейчас матчинг идет только по `primaryPhoneNumber` каждого поля. Дополнительные номера (`additionalPhones`) в первой версии не проверяются — это ограничение GraphQL-фильтра Twenty на массивах JSON.

## Ограничения первой версии

- Одно приложение = одна интеграция с Binotel (один API-ключ). Если нужно несколько — установи приложение несколько раз.
- Матчинг только по primary phone (см. выше).
- Привязка только к объекту **Заявки** (`nameSingular: zayavka`). Если объект называется иначе — измени константу `ZAYAVKA_NAME_SINGULAR` в `src/constants/universal-identifiers.ts`.
- Нет исходящих вызовов click-to-call через API Binotel (пока). Это запланировано на следующую итерацию.

## Структура приложения

```
src/
├── application-config.ts                 — конфиг приложения, serverVariables
├── constants/
│   └── universal-identifiers.ts          — все UUID-константы в одном месте
├── roles/
│   └── default-role.ts                   — роль для logic functions
├── objects/
│   └── binotel-call.object.ts            — объект "Звонок" с полями и SELECT-ами
├── views/
│   └── all-binotel-calls.view.ts         — представление "Все звонки"
├── page-layouts/
│   └── binotel-call-record-page...ts     — карточка звонка
├── navigation-menu-items/
│   └── binotel-calls.navigation...ts     — пункт меню "Звонки Binotel"
├── logic-functions/
│   └── handle-binotel-webhook...ts       — webhook-обработчик
└── utils/
    ├── normalize-phone.ts                — нормализация телефонного номера
    ├── find-phone-fields-on-zayavka.ts   — Metadata API: найти PHONES-поля
    └── match-call-to-zayavki.ts          — матчинг Заявки по номеру
```

## Разработка

```bash
# В корне приложения
yarn install
yarn twenty app:dev

# Тесты
yarn test
```

Используется SDK `twenty-sdk@0.9.0` и `twenty-client-sdk@0.9.0`.
